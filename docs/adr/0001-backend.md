# ADR 0001: Backend stack and hosting

- **Status:** Accepted
- **Date:** 2026-11-07
- **Issue:** [#2](https://github.com/noddle-Cake/grantit/issues/2)

## Context

Grantit is a static React app running on demo data stored in the browser. Phase 2 splits the work between two
people building at the same time (Chris: AI application workflow; Sam: financial tracking and validation), so
Phase 1 has to settle the runtime, database and repo layout first.

Constraints:

- `web/src/types.ts` was written framework-free so an API could share it, and the business rules in
  `web/src/lib` (spending per funding period, compliance flags, word limits, permissions) are pure functions with
  unit tests. The server has to apply the same rules the UI shows.
- Hosting is the 5820 home server: rootless podman containers behind nginx, reached only through the Cloudflare
  Tunnel (`docs/deploy.md`). CI cannot reach it.
- The drafting service will call the Claude API, and the key must stay on the server.
- Later work (sign-in, organizations, QuickBooks sync, audit trail) needs a relational, multi-user store.

## Options considered

| | TypeScript API (Node + Hono) | Python API (FastAPI) |
|---|---|---|
| Shared domain model | Imports the same types and rules as the web app | Re-implemented; types synced through generated OpenAPI clients |
| Rules written once | Yes | No: finance flags and word limits exist twice |
| Languages for the team | One | Two |
| AI / data libraries | Anthropic TypeScript SDK covers what drafting needs | Broader ecosystem |

| | Postgres | SQLite |
|---|---|---|
| Multi-user writes | Yes | One writer at a time |
| Ops on 5820 | One more container, `pg_dump` backups | A file, copy to back up |
| Fit for auth, QuickBooks, audit trail | Good | Would likely be migrated later |

Cloudflare Workers + D1 was ruled out because the site moved off Workers to 5820.

## Decision

- **Language:** TypeScript end to end. Node 24 runs the API's `.ts` files directly (type stripping), so the API
  has no build step.
- **API:** [Hono](https://hono.dev) on `@hono/node-server`, with request validation in [Zod](https://zod.dev).
- **Database:** Postgres 18, accessed through [Drizzle ORM](https://orm.drizzle.team). Migrations are SQL files
  generated by `drizzle-kit` and checked in.
- **Repo layout:** one npm workspace with three packages:
  - `shared/` (`@grantit/shared`) holds the domain types, the pure business rules with their tests, and the
    sample data
  - `api/` (`@grantit/api`) is the HTTP API, database schema, migrations and seed script
  - `web/` is the React app, importing from `@grantit/shared`
- **Hosting:** two more rootless containers on 5820 next to the existing nginx site: the API and Postgres. nginx
  proxies `/api/` to the API, so the browser sees one origin (no CORS, and the auth cookie later is first-party).
  Secrets (database password, Claude API key) live in an env file on 5820 that is readable only by the service
  user, never in the repo. A nightly `pg_dump` goes into the site directory that `srv-backup` already covers.
  Deploy details are tracked in #7 (Phase 4).
- **Local development:** `compose.yaml` runs Postgres in Docker; the API and web run with `npm run dev`.

## Consequences

- Finance and drafting rules have one implementation, tested once and imported by both the UI and the API.
- The web app's import paths change from `@/lib/...` to `@grantit/shared/...` for the moved modules.
- CI needs a Postgres service for API tests.
- The 5820 deploy script builds from the workspace root (`npm ci` at the root, then the web workspace).
- If the AI work later needs Python-only tooling, it can run as a separate service behind the same API without
  changing this decision.
